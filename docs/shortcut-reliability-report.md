## Behavioral implementation

- Ordinary application favorites retain their row, intent, placement, screen, container, and rank while package/component availability is unresolved. Protected folder children remain model members, preventing empty-folder/page pruning from inferring that their positions are vacant. Existing corrupt-intent, removed-profile, invalid-placement, widget, deep-shortcut, archive, and restore-placeholder paths remain specialized.
- The centralized policy uses positive exact-component resolution, known installation storage history, per-profile recovery, and confirmed-uninstall row snapshots. Boot completion, time, unrelated applications, and any mounted volume are not deletion/recovery evidence. Known internal applications outside recovery retain normal loader/update policy; unknown migration history is preserved provisionally.
- A checksummed, schema-versioned, AtomicFile journal lives in no-backup storage per workspace database identity. It records stable profile serial/package history, storage UUID/public mapping when provable, component/item recovery, event generation, and pending uninstall fingerprints. Corrupt/unreadable/unsupported metadata becomes unknown history, not a favorites purge.
- Auxiliary database identity and per-insert row-incarnation tables/triggers are installed non-destructively without changing the favorites schema version. New/cleared layouts, Android restores, and local Lawnchair backup restoration renew identity/incarnations. A reused maximum ID with identical intent, component, profile, and millisecond timestamp cannot match the previous insertion's tombstone. Journal schema 2 retains schema-1 reading; an unverifiable legacy/unknown incarnation never grants removal authority. Public-volume mapping uses only matching UUID evidence from API-29-compatible public APIs; unmapped adopted storage stays unknown. No hard-coded paths or newer volume callback APIs are used.
- Consequential package tasks are captured before enqueue, journaled before the unloaded-model discard gate, and drained at loader checkpoints. Confirmed uninstall invalidates a frozen binding generation at callback receipt, fences already-entered/queued/deferred binding and bind-ID allocation, and reloads healthy deferred items without deleting their favorites. Pending deletes match database, row, stable profile serial, original intent, component, modification fingerprint, and insertion incarnation, not a broad later package query.
- `OP_UPDATE` and `OP_ADD` recover an existing exact target in place. Recovery clears only NOT_AVAILABLE, preserving quiet/locked/suspended and other flags; a different launcher activity does not rewrite a protected intent. Positive target observations that conflict with later package/activity/cursor queries latch durable recovery rather than permitting fallback/deletion. Successful ordinary updates retain normal progress/resizability/archive reconciliation for the exact target. UI binding/removal guards use captured values and perform no package/database lookup on the UI thread.
- Foreground, package availability, boot, and media events request coalesced model-thread revalidation. While foreground, unresolved items retry with 1–30-second backoff without expiry-based deletion. Pause/destroy stops repeated work and unregisters observations at app-state teardown.
- Normal last-valid labels/icons are snapshotted through Lawnchair's custom-label/custom-icon pipeline. Explicit override/global pack resolution returns provenance separately from stock fallback; unresolved custom resources or not-yet-loaded override metadata cannot overwrite the last valid custom snapshot. Both refresh and deferred ContentWriter persistence validate/rasterize the selected drawable. Unavailable live low-resolution folder children hydrate from favorites, and queued high-resolution requests dispatch to the durable snapshot at worker execution instead of an evicted package cache. Migration can recover an existing IconCache image before later eviction. Unavailable taps explain that the shortcut is retained and request revalidation.
- Dirty journal persistence retries during unchanged evaluation/observation, replay, and foreground revalidation. Dirty internal history or unproven row incarnations cannot authorize inferred deletion. Repositories cancel only their owned collector scope and borrow, rather than close, their DAO database; sandbox cold loading never cleans the real application's on-disk layouts.
- Existing retained applications are excluded from automatic install-queue/deck additions, including queues persisted before model loading. No recovery path inserts a new favorites row.
